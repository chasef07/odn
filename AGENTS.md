# Agent rules

Run `npm run check` before every push. CI runs the same command on every pull request.

Each rule below names the check that enforces it. A rule that no check enforces does not belong in this file.

| Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Enforced by                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Code is formatted with Prettier. Run `npm run format` to fix it.                                                                                                                                                                                                                                                                                                                                                                                                            | `npm run format:check`                                                                                                                     |
| ESLint passes with zero warnings.                                                                                                                                                                                                                                                                                                                                                                                                                                           | `npm run lint`                                                                                                                             |
| No comments in JS or TS files, except tool directives such as `eslint-disable` and `@ts-expect-error`. Run `npx eslint --fix` to delete them.                                                                                                                                                                                                                                                                                                                               | `eslint-rules/no-comments.mjs`, in `npm run lint`                                                                                          |
| No comment lines in YAML, TOML, Dockerfiles, ignore files, `.env` files, the Prisma schema or JSON. A shebang and leading Dockerfile parser directives are allowed. `prisma/migrations` is skipped because it is applied history.                                                                                                                                                                                                                                           | `scripts/check-comments.mjs`                                                                                                               |
| Source files and test files typecheck.                                                                                                                                                                                                                                                                                                                                                                                                                                      | `npm run typecheck`, with tests included by `tsconfig.json`                                                                                |
| An intake step page has no `setError` call. A rule belongs in its step schema in `src/lib/validation-schemas.ts`, so the server runs it too.                                                                                                                                                                                                                                                                                                                                | `src/lib/__tests__/intake-step-pages.test.ts`, in `vitest run`                                                                             |
| A rule that `main` enforced at checkout before shadow mode is `always` in `src/lib/intake-rules.ts`, so it blocks checkout whatever `INTAKE_VALIDATION_ENFORCED` says. Only a rule marked `flag` follows the flag.                                                                                                                                                                                                                                                          | `src/lib/__tests__/intake-checkout-differential.test.ts`, in `vitest run`                                                                  |
| Tests pass.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | `vitest run`, in `npm run check`                                                                                                           |
| Every npm script, `npx` tool and repo path named in `AGENTS.md` or `README.md` exists.                                                                                                                                                                                                                                                                                                                                                                                      | `scripts/check-doc-refs.mjs`                                                                                                               |
| Server code reads env vars only through `env` in `src/lib/env.ts` and `publicEnv` in `src/lib/public-env.ts`, never `process.env`.                                                                                                                                                                                                                                                                                                                                          | `eslint-rules/env-sdk.mjs` (`local/no-process-env`), in `npm run lint`                                                                     |
| SDK clients (`Stripe`, `Resend`, `PrismaClient`) are constructed only in their owner module.                                                                                                                                                                                                                                                                                                                                                                                | `eslint-rules/env-sdk.mjs` (`local/no-sdk-client`), in `npm run lint`                                                                      |
| Config is read and SDK clients are built inside functions, never when a module is imported.                                                                                                                                                                                                                                                                                                                                                                                 | `eslint-rules/env-sdk.mjs` (`local/no-import-time-config`), in `npm run lint`                                                              |
| The server exits at startup, naming each variable, when a required env var is missing or invalid.                                                                                                                                                                                                                                                                                                                                                                           | `src/instrumentation.ts` and `src/lib/env.ts`                                                                                              |
| Every admin server action is built with `adminAction`.                                                                                                                                                                                                                                                                                                                                                                                                                      | `eslint-rules/admin-server-action.mjs` (`admin/server-action`), in `npm run lint`                                                          |
| Only `src/db` talks to the database. Callers use its table modules and `src/db/types.ts`. Nothing else imports `@prisma/client`, `pg`, `src/db/client.ts` or the `src/db` query kernel (`sql.ts`, `table.ts`, `tables.ts`, `pool.ts`). Tests mock `src/db` functions.                                                                                                                                                                                                       | `eslint-rules/db-boundary.mjs` (`local/db-boundary`), in `npm run lint`                                                                    |
| Schema changes are numbered SQL files in `src/db/migrations/`, named like `0001_baseline_production_schema.sql` and applied by `npm run db:migrate` in one transaction each. An applied file is never edited: the runner stores its sha256 and refuses on a mismatch. Prisma-era history is adopted once by hand with `npx tsx scripts/adopt-prisma-migrations.ts`, never automatically.                                                                                    | `src/db/migrate.ts`, `src/db/__tests__/migrate.db.test.ts`                                                                                 |
| Database tests are `src/db/**/*.db.test.ts` and run against a PGlite built only from the migration files. `npm run test:db` runs them alone; `npm run test:unit` runs the rest without a database.                                                                                                                                                                                                                                                                          | `vitest.config.ts` (`db` and `unit` projects), `vitest.db-setup.ts`                                                                        |
| A query's text carries one statement. `src/db/pool.ts` runs every query in the extended protocol, so a second statement in the text is rejected instead of run.                                                                                                                                                                                                                                                                                                             | `src/db/__tests__/db.db.test.ts`, in `vitest run`                                                                                          |
| `db.*` and `db.transaction` called inside a transaction callback run on that transaction's connection; a nested `db.transaction` is a savepoint and releases it when it returns. A nested `db.transaction` that starts while a sibling is still open rejects, because savepoints are a stack. A `tx` handle throws once its transaction has finished. A transaction whose connection drops rejects with the connection error and discards the client; the process stays up. | `src/db/__tests__/db.db.test.ts`, in `vitest run`                                                                                          |
| Every column in `src/db/tables.ts` names its kind (`text`, `int`, `bool`, `timestamp`, `date`, `enum`; `jsonCol` and `nullableJson` are `jsonb`). The kind must fit the domain type in `src/db/types.ts` and match the migrated column type. An enum column's type has exactly the labels its status constant in `src/db/types.ts` exports.                                                                                                                                 | `npm run typecheck` (`ColumnFor` in `src/db/table.ts`, pinned by `src/db/__tests__/table.test.ts`), `src/db/__tests__/schema.db.test.ts`   |
| Each WHERE conjunct, JOIN ON condition, ORDER BY, LIMIT, OFFSET and `and()`/`or()` predicate in the SQL of a `src/db` module has a test in its `src/db/__tests__/<module>.db.test.ts` that fails when it is dropped or broken. A mutant that cannot change behavior is allowlisted in `scripts/check-db-mutants.mjs` with the reason.                                                                                                                                       | `npm run check:db-mutants`, one module per job in the `db-mutants` matrix of `.github/workflows/ci.yml` when `src/db` or the check changes |
| The Prisma schema is valid.                                                                                                                                                                                                                                                                                                                                                                                                                                                 | `npx prisma validate`, in `.github/workflows/ci.yml`                                                                                       |
| The production build succeeds.                                                                                                                                                                                                                                                                                                                                                                                                                                              | `npm run vercel-build`, in `.github/workflows/ci.yml`                                                                                      |
